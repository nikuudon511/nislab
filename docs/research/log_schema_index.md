# Log Schema Index

Last updated: 2026-07-25 JST

This file describes the result files generated by the evaluation wrapper and how
to treat them as a small relational dataset.  Use this before adding new plots
or interpreting old result directories.

## Result Directory Layout

Each clean new run should have this shape:

```text
results/<run_name>/
  summary.csv
  <method>/
    run_config.txt
    summary.csv
    observation.csv
    channel.csv
    route.csv
    cpm_input_diag.csv
    rsu_prediction.csv
    stdout.txt
    resource_usage.txt
```

Old runs may not have `run_config.txt` and may lack recently added columns.

## Relational Model

| Table/file | Granularity | Join key | Main purpose |
|---|---|---|---|
| `run_config.txt` | one row per run | result directory | Exact runtime configuration |
| method `summary.csv` | one row per method run | result directory + method | Final aggregate KPIs |
| top-level `summary.csv` | one row per method in a batch | result directory + method | Batch-level summary |
| `observation.csv` | one row per observation time | result directory + method + `time_s` | Time-series metrics and p90/p99 source |
| `channel.csv` | one row per channel sample | result directory + method + time | NR sidelink CBR/channel diagnostics |
| `route.csv` | one row per route sample/event | result directory + method + time | Route-control diagnostics |
| `cpm_input_diag.csv` | CPM input diagnostic samples | result directory + method + time | CPM object/input diagnostics |
| `rsu_prediction.csv` | one row per prediction sample | result directory + method + time | RSU/traffic prediction diagnostics |
| `stdout.txt` | one text log per run | result directory + method | Human-readable interpreted settings and final metrics |
| `resource_usage.txt` | one text log per run | result directory + method | Exact command and resource usage |

## Canonical Run Keys

Use these fields to identify a run:

| Field | Source | Notes |
|---|---|---|
| `run_id` | experiment index ID, e.g. `EXP-004` | Human-managed stable ID |
| `result_dir` | `experiment_index.md` | Path under `results/` |
| `method` | `summary.csv`, wrapper method directory | Example: `v2n2v-adaptive-probability` |
| `SUMO_SEED` | `run_config.txt` | Seed for traffic/mobility |
| `RNG_RUN` | `run_config.txt` | ns-3 RNG run |
| `TTL high/low` | `run_config.txt`, `stdout.txt` | Must be 0.2/0.2 for final runs |
| `MEC_IDEAL_RMR_MODE` | `run_config.txt`, `stdout.txt` | Must be explicit for clean RMR interpretation |

## Primary KPI Columns

Prefer these columns for main comparisons.

| Concept | Preferred column | File | Notes |
|---|---|---|---|
| ORR | `object_recognition_rate` or `orr` | `summary.csv`, `observation.csv` | Main recognition KPI |
| High ORR | `high_priority_object_recognition_rate` | `summary.csv` | High-priority recognition |
| Low ORR | `low_priority_object_recognition_rate` | `summary.csv` | Low-priority recognition |
| MEC update failure | `mec_update_failure_rate` | `summary.csv`, `observation.csv` | Application valid-update failure |
| MEC valid update success | `mec_valid_update_success_rate` | `summary.csv`, `observation.csv` | Positive form of update success |
| MEC AoI p99 | `mec_aoi_p99_ms` | `summary.csv`, `observation.csv` | Freshness tail |
| MEC required DL p99 | `mec_dl_required_mbps_p99` | new `summary.csv` | For old runs, compute from `observation.csv` |
| MEC required/capacity p99 | `mec_dl_required_load_ratio_p99` | new `summary.csv` | Not clipped |
| High fresh redundancy >=2 | `receiver_high_fresh_redundancy_ge2_200ms_rate` | new `summary.csv`, `observation.csv` | High-priority redundancy KPI |
| High RL >=1 / >=2 | `receiver_high_rl_ge1_rate`, `receiver_high_rl_ge2_rate` | new `summary.csv`, `observation.csv` | High-priority redundancy diagnostics |

## Observation-Only or Time-Series Columns

Use `observation.csv` when a metric needs time-series behavior or was not yet
promoted to summary in old runs.

| Concept | Column | Notes |
|---|---|---|
| MEC DL offered/required Mbps, old name | `mec_dl_offered_mbps` | Existing old column; equivalent to required DL Mbps for old runs |
| MEC DL required Mbps, new name | `mec_dl_required_mbps` | Preferred new observation column |
| Clipped DLBR | `mec_dl_busy_ratio` | Saturates at 1.0 |
| MEC forwarded packets | `mec_forwarded_packets` | Receiver-wise downlink transmissions |
| MEC forwarded bytes | `mec_forwarded_bytes` | Downlink bytes after fanout and packet-size accounting |
| NR CPM payload total | `nr_cpm_size_bytes_total` | CPM payload evidence |
| NR RMR deleted total | `nr_rmr_deleted_total` | NR object deletion count |
| MEC payload deleted total | `mec_rmr_payload_deleted_total` | New split counter |
| MEC fanout deleted total | `mec_rmr_fanout_deleted_total` | New split counter |

## Old-Run Compatibility

Old runs before 2026-07-25:

- may use `--low-priority-cpm-recognition-ttl=0.5`;
- do not have `run_config.txt`;
- do not have `mec_dl_required_mbps_*` summary columns;
- do not have split `mec_rmr_payload_deleted_total` and
  `mec_rmr_fanout_deleted_total`;
- may require reading `resource_usage.txt` to recover the command line.

For old required DL p99:

1. Read `observation.csv`.
2. Use `mec_dl_offered_mbps`.
3. Compute p99 over the observation samples.
4. Record in `experiment_index.md` as an old/diagnostic value.

## Clean-Run Requirements

A result can be promoted to `main` only if:

- `run_config.txt` exists;
- `stdout.txt` prints interpreted TTL and MEC ideal RMR mode;
- TTL high/low is 0.2/0.2;
- `MEC_IDEAL_RMR_MODE` is explicit;
- summary includes required DL load columns;
- summary or observation includes high-priority redundancy columns;
- the result is registered in `experiment_index.md`;
- associated claims are registered in `claim_evidence_index.md`.
